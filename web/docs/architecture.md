# Web 模块与会话生命周期

## 概念与职责

Web 观察 Conversation 中的 Message，并让用户向 Actor 发言。主对话与 Operator 工作会话
采用不同布局，但共享消息读取、合并与恢复规则。页面连接和导航不代表业务工作的生命周期。

`app` 选择当前会话并组装页面；`actors` 拥有参与者发现与目标选择；`conversations` 拥有
会话数据的挂载、分页、同步和提交流程。`messages` 拥有消息类型、正文与 block 展示，
`operator` 拥有工作会话关联及并行布局。各模块的 API 函数使用 `transport`，纯类型和
合并函数不依赖传输实现。HTTP JSON 保留 Server 的字段命名，不额外维护同义字段映射。

## 数据流程

打开会话时先取一页元信息，接近可见区域的消息再读取正文；引用跳转可以单点读取被引用消息。
SSE 交付实时快照和 patch，断线重连后按已知消息身份检查元信息，再补齐新增消息。
主对话和工作会话都由 `useConversationMessages` 组合这些能力。

Actor 选择、输入框草稿和消息选择是 UI 状态。发送过程中的文字以临时发送状态展示；API 成功
返回持久 Message 后再进入消息集合。提交失败保留可重试的输入，不将未成功写入的数据标成
已发送。新建会话与首次发言是两次请求：已创建的会话在发送失败后可以复用。

Ask/Confirm 的输入状态由 Human 交互 Hook 管理。收到回复结果后，将问题和回复消息合并到
所属会话；Operator 面板可以将结果交给主会话，主会话只接收 conversation_id 匹配的消息。
明确的 reply_to_id 和 Human block 决定交互含义，普通文本不推断为批准。

## 关键设计

### 导航身份约束异步结果

每次打开会话都创建独立的 UI 生命周期。离开 A、打开 B、再返回 A，最后一次 A 也不会接收
第一次 A 的旧回调。读取请求随生命周期取消，回调同时验证归属；写请求可能已经到达 Server，
即使页面离开也不能假定它没有执行。迟到的创建结果可以加入会话列表，但不能改变新的导航选择。

### 合并规则独立于布局

消息集合按 ID 寻址、revision 判断新旧。元信息在同 revision 下保留已经加载的正文；更新的
元信息让旧正文失效，后续按需读取或 SSE 快照恢复。发现游标、历史游标和流式序号彼此独立。
普通消息列表与 Operator 并行列复用这些规则，各自处理滚动位置和选中样式。

### 连接生命周期归传输与订阅所有

短 HTTP 请求统一处理超时与响应错误。SSE reader 在正常结束、解码失败或调用方退出时释放；
每次重连使用新的取消信号，修复请求也属于这一连接尝试。Message 的 end 不结束 Conv 订阅。
传输失败可以显示为页面错误，成功同步后清除；它不改变消息或 Harness Run 的业务终态。

### 已知类型收窄，扩展类型保留

AgentUE 校验基础模型并应用 patch。Human 卡片额外校验已知字段后才展示输入控件；result
按 text/JSON 渲染。普通文本、Markdown、工具内容及未知业务 block 走内容渲染入口。
当前类型集合使用显式分派，不引入动态插件注册机制，也不将协议扩展封闭为固定枚举。

生命周期回归需要实际挂载 React，验证会话切换、迟到提交、Human 回复及 SSE 重连；纯函数
与静态渲染测试分别验证 revision 规则、并行布局和内容显示。
